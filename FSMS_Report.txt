This document presents the complete, updated system requirements and design specification for

File Status Management System – Logistics Department

1

Objective
The File Status Management System is designed to digitally track and manage the movement of
files within the Logistics Department. The system provides real-time visibility of file status,
ensures accountability at each stage, and enables structured monitoring through a dedicated
Information Kiosk.
The system replaces manual tracking with a centralized digital platform integrated with
role-based access control and QR-based file identification. Internal staff interact with the system
through individual role-specific logins, while end users at the departmental level access file
status through a shared department login on the kiosk interface.

Scope
The system will be implemented across multiple departments and units within the organization.
The following units are within the scope of this deployment:
– Logistics
– INAS 321
– INAS 324

– INAS 333

End users belonging to any of the above departments can select their respective department
through the Information Kiosk interface to search and view file status.

within the overall platform:

User Groups and Access Model
The system operates with two fundamentally distinct user groups. These groups differ in their
mode of login, level of access, and purpose within the system.

A. End User (Departmental Kiosk User)
The end user is the kiosk-side user who accesses the system solely to view file status. A critical
design decision is that each department is assigned one shared login credential. For example, if
30 authorized personnel from the Logistics Department use the kiosk, all 30 individuals use the
same single department user ID.
End users can:
– Log in using the shared department user ID
– Search files by From Date, To Date, and SMS Reference Number
– View the search result table
– Click on a record to view detailed file status
– View status summary and final status
End users cannot:
– Update any file data or remarks
– Access QR scanning functionality
– Access the administrative reports module
– Access the flowchart module (unless explicitly permitted in future)
– Create or edit file records

B. Internal Staff and Admin Users
Internal staff are system users with individual, role-specific credentials. They are responsible for
processing files, updating status, and managing the system. Unlike end users, each internal staff
member has a distinct login tied to their designated role.
Internal staff include:
– B Logo (Super Admin)
– D Logo (Admin)
– Inward Staff
– Mailman Staff (Internal and External)
– IFA
– Store Office
– Others as required

Inward – Role Detail
Inward is the primary application operator for all files. Inward is the sole user responsible for
updating file status within the application. Even when other roles such as D Logo write physical
remarks or when files move through Mailman, it is always Inward who records those updates in
the system.
Inward can:
– Open and submit the file entry form
– Enter all file metadata
– View complete file details
– Update full file status and remarks
– Update receive, submit, and current-with-Mailman events

Mailman – Role Detail
There are two types of Mailman: Internal Mailman and External Mailman. Both operate under the
same restricted permissions. Mailman holds a separate user ID and is concerned only with file
movement events. Mailman cannot view full file details, process file content, or make decisions
regarding remarks.
Mailman can update only:
– Received
– Submitted
These movement updates are visible to end users on the kiosk interface.

CO Sir and IFA – Approval Logic
The approval authority depends on the financial value of the file:
– If amount is Rs. 1 lakh or below: CO Sir can approve
– If amount exceeds Rs. 1 lakh: the file must go to IFA for approval
IFA approves the transaction and releases the budget. This is a mandatory routing rule and not
optional.

– Allows operational tracking using scanning devices

Workflow

3. The corresponding file details are opened directly
4. Access to file details is governed by the user's role permissions

File Movement Workflow
The system follows a structured file movement process. Mailman is used as the physical courier
between Inward and all approval authorities including D Logo, B Logo, CO Sir, and IFA. D Logo
writes remarks on the file. Inward is always responsible for recording status updates in the

application after each movement.

Step-by-Step Flow
1. Inward receives the file and updates the system
2. File is dispatched via Internal or External Mailman
3. Sent to D Logo, B Logo, CO Sir, or IFA as required by the process
4. Remarks or decisions are returned (D Logo writes remarks; CO Sir or IFA approve)
5. File returns via Mailman; Mailman updates Received/Submitted events
6. Inward updates the application with the new status and remarks
7. Further processing continues as below

Detailed Movement Sequence
Step 1: Inward → Mailman → D Logo
Step 2: D Logo (Verification & Remarks) → Mailman → Inward Inward records remarks
(e.g., Approved) in the system
Step 3: Inward → Mailman → B Logo
Step 4: B Logo (Verification) → Mailman → Inward
Step 5: Inward → Mailman → CO Sir
Step 6: CO Sir (Final Approval – for amounts ≤ Rs. 1 lakh) → Mailman → Inward
Step 7: Further processing stages:
– Store Office
– IFA (Financial Approval – mandatory if amount exceeds Rs. 1 lakh)
– Return to Store Office
– Tender Preparation and Upload
This workflow ensures full accountability and traceability at every stage of file movement.

Operational Context – Store Office
In the real-world process flow, the Store Office is required to prepare an Availability Report
before the file is forwarded to CO Sir. This is an operational process detail and is not necessarily
a mandatory software feature in the current version. It should be noted as operational context
and may be added as a system feature in a future release.

System Workflow Summary
1. File is entered by the Inward user through the entry form
2. A unique QR code is generated and attached to the physical file
3. File moves through the defined approval hierarchy via Mailman
4. Each stage is updated in the system by Inward, with Mailman recording movement events
5. The system maintains a complete digital audit trail of all actions and remarks
6. The Information Kiosk displays live file status to authorized department users
7. QR scanning by Inward or Admin retrieves full file details instantly

Key Features
– Centralized file tracking system for the Logistics Department
– Two-tier user model: shared kiosk login for end users, individual logins for internal staff
– Role-based access control with B Logo as the root authority
– QR-based file identification restricted to Inward and Admin users

Conclusion
The File Status Management System ensures efficient, transparent, and accountable handling of
files within the Logistics Department. By integrating QR tracking, role-based workflows, and
real-time status updates, the system significantly improves operational efficiency and reduces
manual dependency.
The updated design distinguishes clearly between end users and internal staff, enforces strict
permission boundaries, and introduces a structured two-type Mailman model. Amount-based
approval routing through CO Sir and IFA ensures financial controls are embedded within the
workflow. All flowchart visualizations are derived from report data and are restricted to
admin-level access.
This document serves as the authoritative reference for system design, development, and
stakeholder communication for the File Status Management System.
